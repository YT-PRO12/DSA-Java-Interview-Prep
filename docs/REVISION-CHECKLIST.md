# Interview practice review checklist

For every solved problem, capture a short record rather than treating a repository file as proof of mastery.

- **Problem:** official problem ID, title, link and difficulty.
- **Pattern:** explain why the chosen data structure or algorithm fits.
- **Invariant:** write the property maintained after every iteration or recursive call.
- **Dry run:** include an ordinary input and at least one edge case.
- **Implementation:** store clean Java code with the platform's actual signature.
- **Cost:** state time and auxiliary space with the correct parameters.
- **Failure review:** record wrong assumptions, compile errors or missed constraints.
- **Revisit:** solve again from memory on a later date and verify independently.

For heap problems, record which item is at the root and why. For trees, distinguish returning a subtree root from returning a single value. For binary search, write the predicate and loop invariant before coding.

Do not mark a submission as accepted unless the external judge has confirmed it.
